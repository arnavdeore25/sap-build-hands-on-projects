# 🔁 Repeat Functionality + Page Parameters – SAP Build Apps

## Scenario

You want to display several items in a reusable layout without creating separate UI blocks for each one. Instead of manually building a duplicate screen for every record, you can use the Repeat component to loop through a list of objects and render the same structure multiple times.

This project also includes a **Page Parameters** example to understand how values can be passed between pages and used dynamically in the UI.

## Solution

This project demonstrates how to use **SAP Build Apps** to iterate through a list of objects and display each item dynamically. The app shows repeated data such as the item name, description, and image in a consistent card or list layout.

It also shows how **page parameters** can be used to pass information from one screen to another, making it easier to build interactive and data-driven apps.

## ✨ Features

- Reuses one layout across multiple records
- Displays data from a list of objects
- Dynamically renders item name, description, and image
- Shows how Repeat works with data binding
- Demonstrates passing values using page parameters
- Helps build cleaner, scalable list-based UIs

## 🧩 Page Parameters

Page parameters are used to send specific values from one page to another. In this project, they help demonstrate how data can be carried across screens, making the app more flexible and reusable.

Typical use cases include:

- Passing an item ID to a detail screen
- Showing different content based on the selected record
- Reusing the same screen with dynamic values

## 📌 Purpose

This project was created as a hands-on learning exercise to understand how the **Repeat** feature and **Page Parameters** work in SAP Build Apps. It highlights how developers can build data-driven interfaces using reusable layouts and dynamic values across screens.
